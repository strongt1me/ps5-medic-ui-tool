# Audit report 12 Nov 2026 (stability, security, compatibility)

[Deutsch](../AUDIT.md) · **English**

Tools: ASAN/UBSAN build of the whole project (`medic-tests`), fuzzer `tests/fuzz_image.cpp` (`medic-fuzz-image <runs> <seed>`), four read-only review passes (security, failure scenarios, silent failures, firmware compatibility). Anything that only runs on the hardware cannot be checked without a console; it is listed below as "open".

## Fixed and covered by tests (host)
| Finding | Fix |
|---|---|
| Use-after-free in `collect_smp_api` (ASAN) | Hits are copied into strings immediately |
| exFAT: cluster count in the header larger than the image (chain loop of up to 2^32 steps) | Cluster count is limited to the image size (`imgread.c`) |
| sqlite WAL: page count from the file was allocated before the 64 MiB limit | Check the limit first |
| Raw firmware value `0x…` turned every game into "needs backport" | Unreadable firmware counts as unknown |
| An error in one collector ended the whole check-up | Each collector is caught individually, fact `collector.failed`; the start page then shows "Check incomplete" (even with an empty rule set), never green |
| History, `update.log`, `config.ini` were replaced by a single line on a read error | Present but unreadable ⇒ do not write |
| Fix engine/journal: an existing but unreadable file counted as "new" (no backup); an unreadable journal counted as "empty" | Abort or error instead of overwriting |
| Snapshot export: user name, `pass`/`pwd`/`login`, `smb://user:pass@…` in the log were not redacted | Extended, `debug.log` is redacted (tests in `test_fixes.cpp`) |
| Launcher killed the pid from the old log with SIGKILL (after a restart possibly kstuff/SM+/fan controller) | Removed, only its own thread name is ended |
| hbldr closed the running app without checking again (a game starts in the 2 s before ⇒ it gets killed) | `hbldr_kill_guard`: check directly before the kill; waiting for the app to end has a 15 s limit |

Fuzzer: 270,000 runs over four seeds without a crash. UBSAN reports only left shifts of negative values in `tweetnacl.c` (third-party code, known to be harmless).

## Launcher changes of 12 Nov (suspicions, not yet tested on the console)
- **Phase file** `/data/ps5medic/launcher.phase` (`launching`/`monitoring`/`failed`/`done`): a new launcher instance never ends the previous one while it is in the ptrace exchange; it waits up to 90 s and otherwise aborts with a message.
- **At most two start attempts**, and the second only if no big app is running (no double start through a hanging LaunchApp call).
- **Test switch without a rebuild:** if the (empty) file `/data/ps5medic/no_budget_syscall` exists on the console, hbldr omits the syscall `sys_set_budget(0)`. Test: create the file, start the UI, then send the launcher again or press the tile while the UI is running. If the console no longer crashes then, S1 is confirmed and the syscall can be dropped permanently. If the UI does not run without it (access to `/data`), it stays on.
- Not implemented: title check of the child process before `pt_attach` (S3), `flock` between launcher/UI/payload (S8) – both cannot be verified without a console.

## PS button in the UI (12 Nov 2026, console tests)
Finding: In the UI (big app FAKE00000) the PS button does not lead to the home screen, there is only a sound; in games and other apps it works. No key event reaches the UI (`ui.log`). **Not the cause** (each tested individually): new UI (SDK 0.45) versus old UI from 9 Nov (`dist/`), new versus old launcher, marker `no_budget_syscall`, test switch `raise_skip` (do not set `uid` and `caps`). SDL calls `sceSystemServiceHideSplashScreen` itself. Even when started via the tile (not only by sending the ELF), only the sound occurs. Open: behavior of other apps started via hbldr/websrv. Suspicion: it is due to the borrowed app FAKE00000 (PSNow eboot); a native app with its own title would not have this problem. Workaround until then: Circle quits the UI (it closes its app itself).
Test switches in the launcher (diagnostics only): `/data/ps5medic/no_budget_syscall` (empty) and `/data/ps5medic/raise_skip` (text `uid` and/or `caps`).

## Open, needs the console (not proven, only suspicion)
1. `hbldr.c`: `sys_set_budget(0)` (syscall 0x23b) when restarting the big app – the author reports kernel panics on older firmwares; matches the crash pattern "UI runs, tile restarts". Test: omit the syscall (the UI uses absolute paths).
2. Tracer process is ended in the middle of the ptrace exchange (new launcher instance) – keep the phase in a lock file.
3. kevent/`NOTE_TRACK` can pick up a foreign child of SceSysCore – check the title before `pt_attach`.
4. Retries (3 × 20 s) can trigger double starts.
5. hbldr mounts `/system_ex` writable and creates `FAKE00000` if it is missing – this contradicts "no write access to /system_ex" in CLAUDE.md (document the exception or remove the path; Marc's decision).
6. No locking mechanism (`flock`) between launcher, UI and payload.

## Second round (12 Nov 2026): read errors and write paths, host tests green (4668 checks)
Fixed:
- `PosixFs::list_dir`: an unreadable entry no longer ends the listing; `file_size` returns 0 instead of 2^64-1 on error; `slurp` checks for read errors (`bad`) and is limited to 256 MiB.
- Error history: if the folder `/system_data/priv/error/history` is missing, the fact is missing (not checked) instead of "0 errors"; an unreadable log is missing as a fact instead of "empty log"; an existing but unreadable `config.ini` is not reported as "missing"; the ELF check distinguishes "unreadable" from "truncated".
- "Fixed/resolved" only if all facts of the rule are present (otherwise it was not checked).
- **Symlink as an intermediate folder:** `PosixRw` refuses to write, append, rename and create folders if, from the third path level on, a folder is a symlink (`/data`, `/mnt/usbN` stay free because they can be mount points). Tests with a real symlink.

Deliberately not changed:
- An unreadable `eboot.bin` of a game without a backport folder remains a "needs backport" finding (cautious, a hint to double-check); an empty process snapshot (sysctl error) is not treated separately, because rules with an empty array do not fire anyway and negative rules use fixtures for this.
- The UI verification after a repair (`Verify::Fixed`) does not check the completeness of the check-up (it would need its own text in five languages).

## Third round (12 Nov 2026): return values, self-test budget, export masking, host tests green (4685 checks)
Fixed:
- `LocalService::run_checkup`: if `append_history` or `save_check` fails, `CheckResult.history_saved = false`; the start page then shows "The history could not be saved" (key `start.history_failed`, five languages) instead of the rule version. Before, the check silently went missing from the history.
- Rule and error-code update (`install_*`, `rollback_*`): if the new file cannot be loaded, the result stays `ok`, but `error = "reload_failed"`; the update page shows "takes effect only after restart" (`update.reload_failed`). Before, the old rules silently stayed in effect.
- `set_language` returns `bool`; the UI deliberately ignores it (the language then applies to the running session).
- Self-test "write test" (`hw.storage.write_verify`): the day marker in the budget is set **before** the first write. If the budget file cannot be written, the test does not start (`budget_unwritable`, skipped). If nothing is written (immediate abort/error), the marker is withdrawn again; if the console aborts in the middle of the test, it does not run again on the same day.
- Snapshot export (D12): `redact_secrets` now also masks MAC addresses (`**:**:**:**:**:**`) and IPv4 (`x.x.x.x`, except loopback and `0.`; version numbers and firmware strings such as `12.00.00.00` stay) and keys containing `account`, `serial`, `email`, `psnid`. Mirrored `param.json`: `titleName` and account/serial-number fields become `***`, `titleId` and firmware fields stay; unreadable JSON is not copied at all. Tests for everything.

Deliberately not changed:
- Signature check of the active `rules.json` on load: after installation there is no `.sig` next to the file any more (it moves to `rules_update/done/`), and file updates (SHA-256) as well as manually copied rules have none at all. A check on load would break these valid paths. The file lives in the dedicated folder `/data/ps5medic/knowledge/`; whoever can write there (FTP) has full control anyway. What is protected is the transport path (signature mandatory for the network download), and loading checks form, regex quality and the text policy.
- Folder and file names in the export mirror stay, because the diagnosis on the PC evaluates exactly these names (payloads, game folders, backport folders); whoever passes the export on should look at it first. Process names stay for the same reason.

Still open: nothing from the three audit rounds that could be fixed without a console; what remains open is what is listed under "Open, needs the console", as well as the second and third rounds on the console (the second has been checked there since the check-up on 12 Nov: start, check-up and quit without errors in the log, repair not).

## Full review (13 Nov 2026): six reviewers, 6773 checks green
Six independent reviews (collectors and parsers, rules and fixes, self-test/report/network, UI, console code including build, data and docs) read the code and proved findings with their own test programs (ASan/UBSan fuzzing, fault injection in the fix flow, random keys across all screens); the core security (PathPolicy, backup, journal, undo, signature chain, text policy of the shipped texts) withstood all runs. Fixed:
- **Repairs:** `smp.scan_depth` writes at most 2 (`clamp_max`; SM+ discards the whole file for `[scan] depth` above 2). `smp_translate_v1_keys` transfers only values that v2 accepts (`smp_v2_value_valid`) and removes only lines that still carry the expected key (line numbers come from the check-up). `autoload_insert_delay` does not let a list grow beyond 4095 bytes. The quarantine and duplicate fixes get a counter (`bad.elf.2`) when the target exists, instead of permanently "target already exists". `smp_disable_conflicting_backpork` leaves already commented-out lines alone. All planners skip entries outside the whitelist with a warning (instead of letting the whole plan fail).
- **Text policy:** now also detects "Neue Firmware installieren/einspielen", "Flash the latest FW", "Update your PS5", "Auf FW 12.00 aktualisieren" (the shipped texts were already clean).
- **Rule loader:** `applies_fw` tolerates spaces after the operator (">= 13.60"); a fact path with two `[]` is rejected (the rule would have silently never fired).
- **Collectors:** an ELF with a read error does not count as broken; a trailing slash on a scan path does not produce a false "hidden" finding; `.ffpkg` counts as an image; the title registry is read up to 2000 lines and, if there are more lines, reports nothing as "not registered" (`appdb.truncated`); an unknown file system type yields `case_sensitive -1` instead of "distinguishes"; an unreadable raw firmware value ("0x…") counts as unknown (`fw.raw`); check-up files with wrong field types no longer discard the whole list.
- **Games view:** registry lines (system apps, add-on content) do not turn a title into a "game"; a finding for `.../Game2/...` no longer also belongs to `.../Game`.
- **Report and export:** credentials are redacted (`password=`, `user:`, `token`, JSON fields, `smb://user:password@host`), also several pairs in one line (`redact_credentials`).
- **Self-test:** throughput (read and write test) counts only the time of the steps, not the pauses of the 33 ms cycle (before, every fast disk appeared as at most ~0.5 GB/s reading or ~120 MB/s writing); the hard deadline of the compute threads uses a monotonic clock; an exception path resets the time start.
- **Network and tooling:** an `update_url` with `#` or `?` is rejected; `medic-sign` creates the key file with 0600 from the start and rejects files over 2 MiB.
- **UI:** long rule texts are no longer cut off after 6 lines (space up to the hint bar, otherwise small font; before, `savedata.foreign_account` lacked the hint "do not delete, back up via FTP"); an incomplete check-up never shows "Everything is fine" in green; the list of unchecked areas is wrapped; the repair preview can be paged through when there are several changes (Up/Down, L1/R1), Cross still applies all of them; a stick direction change needs the high threshold (no extra step when springing back); the title does not run into the reliability line; the header without a model has no dangling separator; the French self-test subtitle fits on one line.
- **Console code:** `TCP_NODELAY` and one piece per small message (header and payload went out in two `send()` calls, the second waited for the delayed acknowledgment of the first); the service has a send timeout of 120 s per send attempt (first 5, then 30 s; Marc: 120 s, so that an app in the background does not lose its session during longer tests); after 'Q' it closes only after `shutdown` and draining the buffer (otherwise RST and the app took 'Q' for a connection loss and restarted the service), the app reads once more after a send error; the pad is reopened with `scePadClose` after 5 s of read errors (30 s "not connected") (new import, entered in `title/native_imports.txt`; the app starts with it on the console, the reopen path itself was not triggered there).
- **Build:** `title/build_native_ui.sh` no longer deletes `build-native/FAKE42007` when the import check is aborted and aborts without `nm`; `make dist` packs all five READMEs; `.pyc` no longer in the repository.
- **Docs:** error code count (150) in the five READMEs, source URL of the 16 rules with the deleted repository, real title IDs from `docs/en/RULES.md`, rule example in `ARCHITECTURE.md`, `SPEC.md`, tile name in `NATIVE.md`, SPDX in `CMakeLists.txt`, `THIRD_PARTY.md` (`native_tilemap.inc`).

Deliberately not changed: (1) The pad test of the self-test can be "passed" with the left stick (stick and D-pad produce the same directions in `PadNav`); the test checks the buttons, not their origin. (2) `getaddrinfo` in the rule download has no timeout of its own (only with a host name with unreachable DNS, the UI then stands still for up to four times 15 s); with an IP address in `update_url` it does not occur. (3) A 16-digit decimal number is not masked as an account ID in the report (it could not be told apart from a timestamp in microseconds).

## Fourth round (13/14 Nov 2026): nine reviewers and a re-check, 6886 checks green
Nine reviews (collectors and parsers, rules and fixes, self-test/report/network, UI, console code including build, data/tests/docs, translations fr/it/es) read the code; most findings are proven with their own test programs. Fixed and covered by `tests/test_review4.cpp`:
- **Crash:** `save_check`, history, self-test files, export and report wrote JSON with the strict `dump()`; a file name or a log line with invalid UTF-8 (Latin-1 via FTP) threw, and the service quit at the end of every check-up. Now `dump_safe` (replaces invalid characters). In addition, the service catches exceptions per session (the app reconnects, the service lives on).
- **Large logs:** `read_tail` reads only the last 4 MiB (SM+ log, ps5-theme log, nanoDNS log; before, everything was loaded, above 256 MiB nothing at all), lines are limited to 2000 characters (a single huge line made `std::regex` blow the stack).
- **Collectors:** `.dat` files without a title ID (e.g. `WPSettings.dat` from "System Volume Information" on USB) no longer produce an `smp.scan_depth` finding, the folder is not scanned; a database under 100 bytes is a finding (`header_bad`) instead of silence; the title of a game takes the next displayable name if the first one contains characters the font does not have.
- **Games view:** a finding for `…/God of War Ragnarok/…` does not belong to `…/God of War` (longest known path wins).
- **Rule loader:** `applies_fw` is validated (operators, versions); `>=13,60`, `13.60-14.10` or `=>13.60` reject the file instead of silently disabling the rule or letting it always fire.
- **Repairs:** an image or ELF file that was set aside is rejected if its size has changed since the preview (a transfer was still running). `PosixRw` rejects symlinks: writing to a link, renaming onto a dangling link, removing an empty folder behind a link.
- **Fix engine texts:** warnings and errors are German with real umlauts (before, ASCII transcription) and English (`libmedic/src/core_messages.cpp`); for French, Italian and Spanish, `libmedic/src/core_l10n.cpp` translates the English fragments including the notes and hints of the fixes. Tests check that every message in `fixes.cpp` and `engine.cpp` and every note has a version in all languages.
- **Text rule:** now also detects "updating/upgrading", fr/it/es with an adjective ("le dernier micrologiciel", "l’ultimo firmware"), "Update your PS5 to the latest version", "Mettez votre console à jour", "Firmware aufspielen", "Systemsoftware neu installieren" as well as variants with a non-breaking space, narrow space, hyphen variants and decomposed accents. A named component ("Update kstuff-lite …") does not trigger a hit.
- **Export and report:** an IPv4 before a sentence period and IPv6 are redacted in the export; in the report also IPv6 behind a label (`inet6:`), `::ffff:a.b.c.d`, account IDs and MACs next to `_`, passwords with spaces (INI notation), `psk=`, `Authorization:` and online IDs; the export reports write errors (full disk) instead of "Snapshot written"; the title of a foreign save game no longer appears in plain text; the placeholders of the account IDs stay 16 characters long from the 9th foreign account on.
- **Self-test:** the kernel log that is read when a self-test starts or before a repair is no longer lost (`persist_klog`); damaged `last.json`/`running.json` no longer throw; the thermal test ends if the service does not advance for longer than 3 s (heartbeat), instead of heating unsupervised until the hard deadline.
- **Console code:** after a long operation (over 250 ms: check-up, download, test) the service discards the pad states that accumulated in the meantime (a pressed Cross could trigger a rule installation on the following screen afterwards); `service.log` is rotated only after the port has been bound successfully (a second instance took the log away from the running one); the app switches to the error screen after 60 s without a first frame; import check with `LC_ALL=C`; the process list does not read beyond the buffer if all attempts end with `ENOMEM`.
- **UI:** the preview of a repair with several warnings no longer overlays the backup line, two lines protruded into the hint bar, `games.d.case` (de) was cut off, ™ ® © no longer appear as "?", 12 unused keys removed, 129 translation corrections (fr/it/es).
- **Fixtures and CLAUDE.md (Marc, 14 Nov):** The fixtures `c2_pos` and `c2_neg` carry an invented title ID (`PPSA00099`, "Test App") instead of that of a real homebrew app; `CLAUDE.md` names the test console with FW 12.00 (PS5 Pro) instead of FW 4.03.
- **Docs and data:** README fr/it/es name twelve fixes, `TESTER.md` names the local network test and "FW 4.00 to 14.10", architecture diagram, numbers in `DIAGNOSE.md`, `rules.example.json` like the real rules, SPDX in `font_data.cpp`, four error codes have their notes again (fr/it/es never saw them because the list lengths did not match); parity test of the five UI languages in `make test`.
- **Re-check (two further reviewers, one of them a regression of mine):** The text rule's exception for a named component switched off the whole verb and let "Update kstuff and the firmware." through; now it applies only if nothing follows the component any more (no "and", comma, "afterwards"). The thermal test counts as aborted (`stalled`) after a stall of the main thread, not as a "performance drop". `::ffff:a.b.c.d.` with a sentence period is fully redacted in the report, `psk` with a space too. When discarding accumulated pad states, Circle stays effective (the self-test abort was lost with steps over 250 ms). `service.log` is opened in append mode (a second instance otherwise fragmented the log). Italian start screen: warning sentence shortened (it was cut off).

Deliberately not changed: (1) `ui/src/app.cpp` and `native_ui_main.cpp` copy every frame completely (not only the changed bands); this is the most likely cause of "somewhat slow", but not measured. (2) `scan_dir` has no upper limit on width; on a USB disk with very many folders the check-up takes longer.

## Sixth round (14 Nov 2026): three reviewers, 6941 checks green
Three reviews (core, service/app/UI, tests/texts/docs) read everything since the state of 13 Nov (commit 1572964); the findings are proven by code or test programs. (The number 6886 of the fourth round is the state before its re-check; 6896 applied at commit 1610f60.)
- **Service/app:** Circle presses from the waiting time after a non-interruptible check-up no longer skip through the screens until quitting (`App::cancellable()`: only the running self-test accepts them). The wait in reading (`StreamReader::pump`) did not take effect on even milliseconds (`now_ms() | 1`); now a marker of its own, a finished frame is not held up. The pad buffer of the service is cleaned up once per pass (before, per message, quadratic). The 60 s without a first frame count from the last data received (an app from the background was otherwise disconnected). The app closes its socket before quitting. An unreadable process list (sysctl ENOMEM) is "unknown" (`IProcessList::readable()`), not "nothing is running".
- **Core:** Text rule "firmware ... verb": every verb in the sentence window counts (a later "update kstuff" no longer hides an earlier firmware update recommendation); "+" in "ShadowMount+" is not an enumeration; the patterns "die Konsole auf ... aktualisieren" do not cross a comma. Redaction: `secret_key`, `private_key`, `access_key`; C++ names such as `Class::Fade::Dead` do not count as IPv6. Export: `klog.txt`, `system.json`, `procs.json` are checked for write errors. `read_tail`: size 0 in the directory entry means "empty or unknown" (read_file clarifies it), a slice that begins exactly at a line start keeps its first line.
- **Tests, texts, docs:** thermal test text in fr/it/es ("controlled by an app"), embedded knowledge texts are now compared with `knowledge/l10n`, `make test` calls `tools/l10n_check.py`, test folders have unique names, the text rule is tested for every alternative spelling, README line (five languages), thermal test table in `docs/en/RULES.md`, `medic` links against `Threads::Threads`, `applies_fw` has a pattern in the schema.
- **Deliberately not changed:** (1) The send timeout of 120 s per `send()` is not an overall deadline per frame (up to 240 s with a stalled app); a deadline would also cut off slow but living readers. (2) `password=value with spaces` without spaces around the "=" redacts only the first word (command lines separate with spaces). (3) Versions such as `fw_12.00.00.10` next to an underscore are redacted as an IP (too much redaction is harmless, an IP let through is not). (4) The export write error and the placeholder account IDs from the 9th foreign account on do not yet have a test of their own.
